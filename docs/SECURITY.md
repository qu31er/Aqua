# Безопасность Aqua

## Что реализовано
| Область | Решение |
|---|---|
| Пароли | bcrypt (12 раундов, соль внутри хэша). Пароль не хранится и не логируется. Требования: ≥ 8 символов, латиница a–z и цифра (проверка на клиенте и на сервере). |
| Сессии | JWT HS256, срок 7 суток, секрет из `AQUA_SECRET_KEY` или `data/secret.key` (права 600). WebSocket: токен отправляется первым сообщением, а не в URL. |
| Перебор паролей | 5 неудач за 5 минут → временная блокировка входа. |
| SQL | Только параметризованные запросы; `LIKE` с экранированием. |
| XSS | Пользовательский текст вставляется через `textContent`; SVG-загрузки запрещены; CSP `script-src 'self'` (без inline-скриптов). |
| Файлы | Белый список MIME, лимит размера (поточное чтение), случайные имена на диске, `nosniff`, доступ только владельцу и участникам чата (в том числе к обложкам видео). |
| Заголовки | CSP, X-Content-Type-Options, X-Frame-Options: DENY, Referrer-Policy, Permissions-Policy, HSTS при HTTPS. |
| Транспорт | В продакшене только HTTPS/WSS (TLS 1.2+) через обратный прокси (nginx/Caddy). |

## Сквозное шифрование (E2E): проект, не реализовано
Сейчас сообщения защищены TLS и хранятся на сервере в открытом виде. Для E2E в личных чатах предлагается схема на WebCrypto:

1. **Ключи.** При регистрации клиент создаёт пару ECDH P-256. Приватный ключ остаётся на устройстве (IndexedDB, `extractable: false`), публичный отправляется на сервер.
2. **Общий секрет.** Для чата A↔B: `ECDH(privA, pubB)` даёт одинаковый секрет у обоих.
3. **Ключ сообщений.** `HKDF-SHA-256(секрет, salt = id чата, info = "aqua-e2e-v1")` → AES-256-GCM ключ.
4. **Шифрование.** На каждое сообщение случайный 96-битный IV; в `text` уходит `base64(iv ‖ ciphertext ‖ tag)`. Файлы шифруются тем же ключом до загрузки.
5. **Проверка собеседника.** Показ «отпечатка» (хэш двух публичных ключей) для сверки вручную.
6. **Ограничения.** Поиск по тексту и просмотр истории на новом устройстве требуют переноса ключа (QR/резервная фраза); для групп нужен отдельный протокол (общий ключ группы с обёртыванием под каждого участника).

## Рекомендации к продакшену
Задать `AQUA_SECRET_KEY`, включить HTTPS, ограничить `AQUA_CORS_ORIGINS`, настроить резервные копии `data/`, запускать за reverse-proxy с rate limiting.
